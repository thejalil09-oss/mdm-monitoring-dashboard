The problem

  • Phones and tablets now carry corporate mail, files and MFA tokens.
  • Organisations lose visibility once a device leaves the office.
  • Out-of-the-box Android is not enterprise-ready: no lock, USB debugging open, unknown-source installs allowed.
  • Commercial MDM (Intune, Workspace ONE) costs money and needs cloud connectivity.

Goal

A self-hosted MDM monitoring and compliance dashboard for an Android fleet — powered by ADB, mapped to CIS & NIST, with a remediation path.

Approach in one picture

Lab architecture: PowerShell collector → ADB server → emulator fleet → dashboard.

Three layers

  • Collect — live state via ADB (identity, lock, encryption, debug, apps).
  • Score — 8-rule baseline, weighted 0–100, per-rule evidence.
  • Act — remediate settings; final lockdown = USB debugging off.

Implementation highlights

Collect (mdm.ps1)

  • One probe per control; adb root for privileged reads.
  • Screen-lock probed by reading locksettings.db via pushed SQL file (fixes Windows shell-quoting).

Score + report (collect.ps1)

  • Writes devices.js + raw JSON snapshot.

Remediate (apply-policy.ps1)

settings put system screen_off_timeout 30000
settings put secure install_non_market_apps 0
settings put global verifier_verify_adb_installs 1
settings put global package_verifier_enable 1
pm disable-user --user 0 com.android.camera2
settings put global adb_enabled 0   # final lockdown

Live demo — the dashboard

What it answers

  • How many devices are compliant / at risk / non-compliant?
  • Which control is failing, and what value did the probe see?
  • What is the fleet average score?

Key finding

Default devices fail 5+ controls out of 8 — including the highest-weight ones (lock, debug, timeout).

The one control that bites back

  • USB debugging off (adb_enabled=0) instantly severs the management channel — device goes offline.
  • Remote re-enable is impossible by design (that is the point).
  • Recovery needs physical access / re-enrolment.

Recommendation

  • Stage the rollout: apply all settings controls first, verify on the dashboard, then disable USB debugging last.
  • Run the collector on a schedule → detect drift, not just point-in-time audit.
  • Production: graduate from ADB to a Device Owner (DPC) enrolment so policy survives reboots cryptographically.

Conclusions

  • An effective MDM monitoring layer is buildable with open tools + ADB, no licence cost.
  • Most mobile risk is default misconfiguration — measurable and cheap to fix.
  • Evidence-backed scoring turns the dashboard into an audit artefact.

Deliverables

  • GitHub repository: collection + enforcement scripts, policy baseline, dashboard, evidence, 25-page report.
  • Printed report (15+ pages) following the prescribed structure.
